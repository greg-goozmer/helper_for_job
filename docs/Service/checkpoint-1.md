# Контрольная точка 1

## Сценарий показа — около 5 минут

1. **Тема и пользователь (30 секунд).** Помощник кандидату: цель → компетенции → оценка → практика → повторная оценка.
2. **Продукт (30 секунд).** Открыть Product/01-context и Product/03-requirements: проблема, scope, проверяемые требования.
3. **Интерфейс (2 минуты).** Выбрать Backend/Middle, посмотреть навыки, разобрать один тренировочный ответ, затем завершить оценку из трёх вопросов.
4. **Следующий шаг (30 секунд).** Открыть результат и план, показать историю. Объяснить, почему тренировка не меняет результат.
5. **Структура и SDD (1 минута).** Показать docs/Product, Tech, Service; цепочку REQ → GWT → проверка; код интерфейса.
6. **Команда и Git (30 секунд).** Таблица README и git log --oneline. Проговорить следующий этап.

Рабочий RAG на первой точке не требуется.

## Пример для демонстрации разбора SQL

```sql
SELECT user_id, SUM(amount) AS total
FROM orders
WHERE created_at >= CURRENT_TIMESTAMP - INTERVAL '1 month'
GROUP BY user_id
ORDER BY total DESC
LIMIT 5;
```

Этот пример иллюстрирует критерии; он не выполняется в приложении.

## Что честно сказать о текущем состоянии

«Сейчас работает браузерное приложение на локальных данных. Процент считает упомянутые критерии по словам. Мы ещё не измеряем реальную готовность и не подключали RAG. Матрица грейдов, источники, retrieval и AI-оценка — следующий этап».

Не утверждать, что LLM уже проверяет ответы, что проценты валидированы или что три роли означают авторство коммитов.
