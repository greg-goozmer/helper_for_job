# Контекст и продуктовая гипотеза

## Проблема

Кандидат готовится по разрозненным вакансиям, статьям и спискам вопросов. Ему трудно понять требования выбранного грейда, проверить пробелы и решить, что учить дальше.

## Целевой пользователь

Начинающий или развивающийся IT-специалист, который готовится к следующему собеседованию либо изучает смежную профессию. Начальный сегмент реального MVP — Backend разработчик уровня Junior/Middle. Frontend и аналитика на КТ1 иллюстрируют расширяемость сценария.

## Ценность

Один маршрут: цель → матрица компетенций → baseline → практика по пробелам → повторная оценка. Гипотеза: конкретный следующий шаг полезнее одиночного общего балла.

Пользовательский результат: знает, какие требования изучать, получает объяснимый разбор и планирует следующую тренировку.

## Объём КТ1

Интерактивный прототип, документация SDD и Git-история. Демо-процент отражает только совпадение критериев по словам. На этом этапе нельзя проверять гипотезу об объективном измерении готовности.

## Будущий MVP

- RAG по проверенным требованиям, вопросам и учебным материалам с указанием источников.
- Матрица компетенций по профессии и грейду, связи между навыками.
- Отдельные training и assessment с оцениванием по рубрике.
- История сопоставимых оценок, рекомендации по gaps.
- Career fit по покрытию требований целевой роли.

## Вне первого MVP

Рекрутинг, отбор сотрудников, гарантии трудоустройства, видеораспознавание эмоций, автоматическая отправка откликов, платёжная система.

## Критерии успеха

КТ1: сценарий можно пройти без объяснений разработчика; документация показывает ограничения и ответственность. Позднее: проверить полезность плана на 3–5 пользователях; качество retrieval и оценивания измерять отдельно. Численные продуктовые цели устанавливаются после baseline.
