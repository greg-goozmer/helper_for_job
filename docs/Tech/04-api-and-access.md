# API и доступ

**Статус: проект контракта. Эти endpoints ещё не реализованы.** Фронт КТ1 не выполняет fetch и не требует логина.

## Предложение для интеграции

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | /api/v1/professions | Профессии и доступные грейды |
| GET | /api/v1/competencies?profession_id=backend&grade=Middle | Матрица компетенций с версией |
| POST | /api/v1/sessions | Создать training или assessment |
| POST | /api/v1/sessions/{id}/answers | Отправить ответ на текущий вопрос |
| POST | /api/v1/sessions/{id}/complete | Завершить, создать отчёт идемпотентно |
| GET | /api/v1/assessments/{id} | Итоговый отчёт и основания |
| GET | /api/v1/profiles/me/plan | Приоритетные пробелы |

### Создание сессии

```json
{ "mode": "assessment", "profession_id": "backend", "grade": "Middle", "skill_ids": ["sql"] }
```

Ответ (пример структуры):

```json
{
  "session_id": "opaque-id",
  "mode": "assessment",
  "rubric_version": "v1",
  "question": { "id": "q-01", "text": "Текст вопроса", "skill_id": "sql" },
  "question_count": 3
}
```

Сервер не передаёт рубрику в assessment до завершения. В training доступны rubric и feedback. КТ1 скрывает рубрику лишь в интерфейсе: она есть в исходном коде, защита от списывания не заявляется.

## Ошибки и безопасность будущего API

- 400/422 — неверный профиль, режим, длина ответа.
- 401/403 — нет сессии пользователя / нет доступа к чужому отчёту.
- 409 — завершённая сессия либо конфликт версии.
- 429 — ограничение частоты; 503 — AI/поиск недоступен.
- Формат ошибки: code, message, request_id, retryable.
- Идентичность и права проверяет сервер; ID отчёта не является разрешением доступа.
- API-ключи LLM — только на сервере, не в браузере и Git.
- Не писать тексты ответов в обычные логи; срок хранения согласовать отдельно.

Открытые решения: аутентификация, провайдер LLM, сроки хранения, точная JSON Schema и бюджет вызовов. Отвечает Ясевичусь Артур.
